# 数据语义层与 AI 数据分析调研

**Semantic Layers & Agentic Data Analysis**

研究企业如何把业务概念、指标计算、数据权限和分析能力，做成 BI、应用与 AI 可以共同使用的基础设施。

每个方案回答四个问题：**谁做的、构建了什么、供给什么场景、为此做了什么设计。** 在此基础上，比较架构取舍与企业落地边界。

资料核查日期：**2026-11-12**。本仓库是公开资料研究与部分源码静态核查，尚未进行产品部署或模型基准复测。

## 核心判断

企业语义层有不同的建设目标，先确定需要统一的对象，再比较产品：

| 建设目标 | 代表路线 | 核心能力 |
| --- | --- | --- |
| 指标与分析计算一致 | Looker、Power BI、dbt、Cube、AtScale | 度量、维度、粒度、关联、查询执行 |
| 数据平台内复用业务定义 | Snowflake、Databricks | 原生语义对象、目录治理、平台计算 |
| 跨系统理解与访问数据 | Denodo | 业务实体、虚拟视图、跨源访问 |
| 以自然语言消费受治理数据 | SuperSonic | 语义映射、查询校正、物理 SQL 翻译 |
| 业务对象与操作闭环 | Palantir | 对象、关系、函数、动作、授权 |
| 自主完成数据分析任务 | DeepAnalyze | 多轮规划、代码执行、反馈、分析产物 |
| 复用并更新 Agent 的语义知识 | EvoOntology | 按需检索、来源证据、版本化演进 |

这里的分类表示架构重心，不表示产品功能互斥。厂商机制与证据见上方专题文档。

**DeepAnalyze 更适合作为受治理数据服务之上的分析执行者。** 指标层负责确定业务口径、计算和权限；模型负责选择分析步骤、处理结果、生成图表和解释。两者的接口与验收需要另行设计，不能假设开箱即用。

## 研究范围与可信度

- 优先使用官方文档、论文、模型卡和代码；不使用厂商宣传中的“第一”“最佳”作为独立结论。
- 明确区分公开文档事实、特定版本源码观察、作者论文结果和本仓库的架构建议。
- 不把数据库连接兼容等同于语义模型兼容，不把 SQL 成功执行等同于业务正确。
- 不收录模型权重、第三方代码副本、企业数据或凭证；上游材料通过链接访问。
- 未进行商业报价、国内可采购性、网络可达性或全产品功能认证；这些需要结合具体企业环境补充。
