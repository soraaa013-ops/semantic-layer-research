# PoC 与验收方案

本文件是可执行的评测设计，不包含产品实测结果。样例均为本仓库构造的虚构数据，与任何企业真实数据无关。

## 1. 首轮范围

选择一个业务域、10—20 个指标、两个消费端和至少两类用户身份。先固定数据快照和人工可验证的结果，再比较产品。

建议覆盖 30—50 个问题，包含常见任务和高风险边界。验收阈值应由业务确认，不从演示表现直接推定。

## 2. 必测场景

| 维度 | 测试问题 | 预期行为 |
| --- | --- | --- |
| 关联 | 一笔订单关联多条明细、退款 | 金额与计数不被无意重复 |
| 比率 | 不同规模分组的比率汇总 | 根据契约重算分子分母 |
| 去重 | 一名用户跨多个日期出现 | 总体去重不简单累加每日去重 |
| 半可加 | 库存余额按月份汇总 | 按契约取期末、平均等，不盲目求和 |
| 时间 | 支付、收入确认与退款时间不同 | 使用指定时间归属 |
| 历史 | 客户级别和地区发生变化 | 正确使用历史或当前属性 |
| 空值 | 无收入、零分母、无数据 | 区分零、未知与无权限 |
| 权限 | 同一问题不同身份 | 返回授权范围并保持缓存隔离 |
| 多义 | “收入”有销售、财务两种定义 | 按上下文选择或请求澄清 |
| 一致性 | BI、SQL、AI 查询同一指标 | 在相同版本和范围下数值相同 |
| 变更 | 指标定义升级 | 可追踪版本、受影响消费端和回归结果 |
| 新鲜度 | 热缓存与新到数据 | 明确数据截止时间，不静默返回过期结果 |

## 3. 可手工核验的关联与比例样例

订单表：

| order_id | customer_id | order_amount |
| --- | --- | ---: |
| O1 | C1 | 100 |
| O2 | C2 | 200 |

退款表：

| refund_id | order_id | refund_amount |
| --- | --- | ---: |
| R1 | O1 | 10 |
| R2 | O1 | 20 |

本例约定：同币种、不含税、不考虑时间差；净收入 = 订单金额合计 − 退款合计。正确结果为 **270**。

将退款直接左连接订单，再对订单金额求和，会得到 100 + 100 + 200 = 400；再减 30 得到错误净收入 **370**。参考思路是先把退款汇总到订单粒度，再与订单关联：

```sql
WITH refunds_by_order AS (
  SELECT order_id, SUM(refund_amount) AS refund_amount
  FROM refunds
  GROUP BY order_id
)
SELECT SUM(o.order_amount - COALESCE(r.refund_amount, 0)) AS net_revenue
FROM orders AS o
LEFT JOIN refunds_by_order AS r ON o.order_id = r.order_id;
```

这是该虚构契约下的参考 SQL，不是适用于所有财务业务的实现。

比例样例：A 组 1/2 转化，B 组 9/90 转化。总体是 10/92，约 **10.87%**，不是两个比例的平均值 **30%**。

## 4. DeepAnalyze 的四组对照

| 组别 | 模型 | 工具与数据入口 | 用途 |
| --- | --- | --- | --- |
| A | 通用模型 | 原始数据查询与 Python | 基线 |
| B | DeepAnalyze | 与 A 相同 | 观察专门训练的收益 |
| C | 与 A 相同的通用模型 | 语义查询与 Python | 观察语义服务的收益 |
| D | DeepAnalyze | 与 C 相同 | 观察组合收益 |

模型与运行协议适配要记录清楚，不能用不兼容协议造成的失败当作能力差异。各组使用相同数据权限、输出要求和执行资源；固定或记录 token、轮数、时间和采样设置。对于随机性任务安排多次运行，报告波动。

至少包含：多文件合并、指标变化解释、数据质量定位、图表报告，以及缺少信息时应澄清的任务。

## 5. 结果评分分开记录

| 指标 | 测量方式 |
| --- | --- |
| 数值正确性 | 与人工确认的结果逐项比较，明确浮点容差 |
| 口径遵循 | 检查时间、粒度、过滤与历史规则 |
| 权限符合性 | 检查授权数据范围、错误消息与派生产物 |
| 执行成功 | 完整完成任务；单独记录重试与超时 |
| 解释可信度 | 每个主要结论能追溯到数据与计算 |
| 可复现性 | 保存数据快照标识、脚本、查询与环境版本 |
| 成本 | 模型调用或 GPU 时间、CPU、扫描量、存储 |
| 延迟 | 冷 / 热查询、端到端 p50 / p95、真实并发 |

报告美观度不能覆盖数值错误；执行成功不能覆盖越权；相关性不能被描述为已经证明的因果。

## 7. 决策门槛

先要求核心业务样例、权限边界和可追溯性符合预先约定，再比较成本与体验。对于开放式研究，应采用业务复核加结构化评分，而不是只看模型互评。上线后持续回放稳定问题集，并单独记录模型、语义版本与数据变化。
